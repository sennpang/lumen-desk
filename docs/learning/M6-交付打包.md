## 核心知识点

### 1. asarUnpack：原生模块打包第一大坑

asar 是把源码打成一个归档文件，Electron 做了虚拟文件系统让 `require` 能读里面的 JS。但 `.node` 文件是**动态链接库**，要按真实文件路径 `dlopen` 加载——虚拟路径无法被动态链接器识别，留在 asar 里必崩。

```yaml
asarUnpack:
  - "**/node_modules/better-sqlite3/**"
  - "**/node_modules/hnswlib-node/**"
```

builder 会把它们原样放到 `app.asar.unpacked/` 并在 asar 内留解包标记，`require` 自动重定向。M6 的验证不是"打包成功"就算完——用包内 Node 直接 `require('app.asar/node_modules/better-sqlite3')` 跑了内存库读写、hnswlib 建索引检索 5 项断言，确认真能加载。

### 2. ABI 重编译为什么是必须的

Electron 内置的 Node 与系统 Node 的 `NODE_MODULE_VERSION`（ABI）可能不同。原生 C++ 插件按某个 ABI 编译，运行时 ABI 不匹配直接拒绝加载。`postinstall: electron-builder install-app-deps` 与打包时的 `@electron/rebuild` 都在干同一件事：针对 Electron 的头文件重编译原生模块。

### 3. 生产环境安全收敛（与开发态的区别对待）

在 [src/main/index.ts](../../src/main/index.ts)：

- **单实例锁** `requestSingleInstanceLock()`：第二次启动直接退出；`second-instance` 时唤起/聚焦已有窗口——否则两个实例抢同一个 SQLite、重复跑后台任务
- **导航拦截** `will-navigate`：单页壳应用拒绝任何整页导航，http(s) 外链转 `shell.openExternal`，`file:`/`javascript:` 等静默拦截
- **打包态收敛**：`app.isPackaged` 时移除默认菜单（含重新加载/DevTools 项）、`webPreferences.devTools=false`。开发态全部保留，调试不受影响
- 新窗口 `setWindowOpenHandler` 也有协议白名单（M5 Agent 的 open_url 白名单之外的第二道闸）

原则：**用 `app.isPackaged` 区分行为，而不是维护两套代码。**

### 4. 未签名应用的分发现实

没有 Apple Developer 账号时 `mac.identity: null` 显式跳过签名，产出 ad-hoc 包，可本机/内网分发。用户首次打开需右键 → 打开（或系统设置里允许），dmg 里放 Applications 软链做拖拽安装。将来要正式分发，再补 Developer ID 签名 + 公证（notarization），配置增量即可。

### 5. 设置备份：密钥为什么不导出

备份文件是 `{kind, appVersion, exportedAt, settings, hasApiKey}` 的 JSON。API Key 由 safeStorage 绑**机器级密钥**加密（Keychain/DPAPI），换机器根本无法解密——导出既无用又是泄露面，只记录"原机器上是否配过 Key"，导入后提示重新填写。

导入链路对外部文件零信任：先验 `kind` 防误选其他 JSON，再经 `sanitizeSettings` 逐字段按类型/枚举校验、只挑已知键、缺字段回退默认值。

### 6. 首次引导的状态设计

不新建表：在 `app_setting` key-value 表加一个 `ui_meta` 行存 `onboardingDismissedAt`。启动时为 null 就弹三步卡（配模型 → 导入资料 → 三种对话模式）。任何退出路径（开始使用/快捷跳转）都先持久化 dismiss 再跳转；查询失败则降级为不弹，引导永远不能挡住主界面。

### 7. 应用图标怎么做才不"AI 模板感"

最终方案（用户审美主导两轮筛选）：[resources/icon.svg](../../resources/icon.svg) 暖墨黑 squircle + 米白圆头粗笔字母 L（竖笔即灯柱）+ 顶端琥珀灯点。刻意不用渐变/光晕/星光。

工程要点：

- **小尺寸优先**：Dock 16px 下只有强对比几何笔画还可辨，复杂场景（书+灯+光）缩到 32px 必糊
- macOS 零三方工具链：SVG 用系统 Swift `NSImage`（11+ 原生支持 SVG）→ `NSBitmapImageRep` 出各尺寸 PNG → `iconutil -c icns` 组 iconset（16~512@2x）
- builder 按 `buildResources: resources` 约定自动拾取 `icon.icns`/`icon.png`，改完图标重跑 `npm run dist`

## 持续交付：GitHub Actions 自动打包分发

本地能打包只是起点，`.github/workflows/` 把发布变成"推一个标签"的事：

### 两条流水线的分工

| 文件 | 触发 | 干什么 |
|---|---|---|
| [ci.yml](../../.github/workflows/ci.yml) | push main / PR | ubuntu 上 `npm ci → typecheck → build`，分钟级红绿信号，保证主干随时可发版 |
| [release.yml](../../.github/workflows/release.yml) | 推送 `v*` 标签 | 三平台矩阵并行打包，产物自动挂到 GitHub Release |

矩阵三行（用**原生架构 runner** 而不是交叉编译，避开原生模块重编译的坑）：

```
macos-14 (Apple 芯片) → electron-builder --mac --arm64 → dmg + zip
macos-13 (Intel)      → electron-builder --mac --x64   → dmg + zip
windows-latest        → electron-builder --win --x64   → NSIS .exe
```

发布流程（版本号在 [package.json](../../package.json)）：

```bash
# 1. 改版本号
npm version 0.2.0 --no-git-version-tag   # 或手改 package.json
git commit -am "chore: release v0.2.0"
# 2. 打标签并推送——workflow 里的防呆步骤会校验 tag 与版本号一致
git tag v0.2.0
git push origin main --tags
# 3. Actions 页面等三个绿灯，Release 页面自动出现带产物的 v0.2.0
```

设计要点（都值得在自己的项目里复用）：

1. **`--publish never` + 统一上传**：builder 只管出包，上传 Release 统一用 `softprops/action-gh-release`，三个并行任务向同一个 Release 追加文件，避免 builder 各自的发布探测
2. **`fail-fast: false`**：一个平台挂了，另外两个照样出包
3. **标签/版本防呆**：`v0.2.0` 标签必须等于 `package.json` 的 `0.2.0`，否则任务失败——防止安装包版本号和 Release 标题对不上
4. **`permissions: contents: write`**：只给上传 Release 所需的最小权限；预发布标签（`v0.2.0-rc1`）自动标 prerelease
5. **缓存分层**：setup-node 缓存 npm 依赖，actions/cache 按平台缓存 Electron 二进制与 builder 依赖（`~/Library/Caches/electron` 等）
6. CI 刻意只跑 typecheck/build **不打包**：把"快速反馈"和"正式产物"两条流水线分开，日常推送不等几分钟的打包

### 未签名分发的边界（当前状态）

- macOS：`identity: null` 出 ad-hoc 包，用户首次右键 → 打开；将来要消除这一步，需 Apple Developer 账号 + Developer ID 签名 + 公证（notarization）
- Windows：NSIS 包无签名，首次运行有 SmartScreen 提示（更多信息 → 仍要运行）；消除需 EV/OV 代码签名证书

### 自动更新（electron-updater，已接入）

从"能分发"到"能自动更新"的完整链路：

- **更新源**：electron-builder.yml 的 `publish: { provider: github, owner, repo }` 有两个消费者——打包时生成 `app-update.yml` 装进应用（electron-updater 运行时读它知道去哪查更新）；builder 自己的发布动作仍由所有脚本/CI 显式 `--publish never` 关掉，产物统一走 softprops 上传
- **更新协议**：electron-updater 不查 GitHub API，而是拉 Release 附件里的元数据文件（Win `latest.yml`；mac `latest-mac.yml`），里面有版本号/文件名/sha512；下载对应安装包（Win 是 NSIS exe，mac 是 **zip** 不是 dmg——Squirrel.Mac 解压 zip 替换 .app），`.blockmap` 支持差量下载
- **产品策略**（src/main/services/update.ts）：启动 10s 后静默**检查**一次（避开启动抢资源），发现版本只通知不下载；设置页手动「下载更新」（进度/速率经 download-progress 事件推送）→「重启并安装」；`autoInstallOnAppQuit=true` 兜底，用户自然退出时也会装上
- **状态机可观测**：checking/available/not-available/downloading/downloaded/error 全部经 `update:event` 广播给渲染端，error 不弹框只落状态（后台断网检查不应打扰），设置页 error 时给 Releases 手动下载链接。经验：**autoUpdater 的 error 必须事件监听，只靠 checkForUpdates() 的 Promise reject 接不住下载阶段的失败**
- **mac 双架构分通道**（关键坑）：两个 mac runner 向同一 Release 目录传文件，默认元数据都叫 `latest-mac.yml` 会互相覆盖。解法是 CI 里把它分别改名成 `latest-arm64-mac.yml` / `latest-x64-mac.yml`，应用内按 `process.arch` 设 `autoUpdater.channel`（electron-updater 对 darwin 会给 channel 自动拼 `-mac` 后缀，`getChannelFilename` 再拼 `.yml`）。yml 内部引用的 zip 名本身带 -arm64/-x64，改名元数据不影响其内容
- **开发态**：`app.isPackaged` 为 false 时直接 unsupported（没有 app-update.yml、版本恒为 0.0.0，发请求毫无意义），IPC 仍注册，UI 显示"仅安装包可用"
- **未签名的现实**：Squirrel.Mac 安装未签名 zip 很可能被系统拒绝，所以 UI 保留手动下载入口；v0.1.0 安装包不含更新模块，必须手动跨一次版本
- electron-updater 是普通运行时依赖，externalizeDepsPlugin 自动外置；类型定义自带，主进程直接 `import { autoUpdater } from 'electron-updater'`

## 打包后的验证清单（下次发版照做）

1. `npm run typecheck` + `npm run build` 通过
2. `npm run dist` 产出 dmg + zip；`@electron/rebuild` 两个原生模块均 finished
3. `app.asar.unpacked/` 下能看到两个 `.node`（含 darwin-arm64 prebuild）
4. 用**包内**二进制 `ELECTRON_RUN_AS_NODE=1` 跑断言：better-sqlite3 内存库读写、hnswlib 建索引检索、主/渲染产物存在
5. 直接启动 `.app/Contents/MacOS/...` 存活（initDb 同步加载原生库不崩）
6. `hdiutil attach` 挂载 dmg，确认含 app + Applications 软链
7. Finder/Dock 若显示旧图标，是图标缓存：`killall Finder; killall Dock`

## 踩坑记录

- **打包后 macOS 复制/粘贴快捷键全部失效**：开发态 Electron 会自动补默认菜单，于是误以为菜单无关紧要，打包时调了 `Menu.setApplicationMenu(null)` 想隐藏未用的顶部菜单栏。结果开发态一切正常，打包后 ⌘C/⌘V/⌘X/⌘A 以及中文输入法候选词的快捷键全部失效——这些编辑命令在 macOS 上由「编辑菜单」里的标准 role（`cut/copy/paste/selectAll`）承载，没有菜单就没有命令路由。正确做法：darwin 下用 `Menu.buildFromTemplate([{ role: 'appMenu' }, { role: 'editMenu' }, { role: 'windowMenu' }])` 保留系统角色菜单（role 菜单由系统本地化为各语言且自动绑定标准快捷键），只在 Win/Linux 才 `setApplicationMenu(null)`（那两个平台编辑快捷键不依赖应用菜单）。经验：**凡是开发态被框架"自动补上"的东西，都要假设打包态没有，专门验证一次**。
- hnswlib-node 3.x 在包内验证时又踩一次 API：`new HierarchicalNSW(space, dim)`、`initIndex(容量)`、`addPoint` 只收普通 Array 不收 Float32Array
- 外置 SSD 上直接运行未签名 .app 会有 `sandbox_extension_issue_file` 提示（非致命）；拖到 /Applications 正常
- builder 的 "Implicit publishing triggered by CI detection" 警告用 `publish: null` 消掉，避免探测发布仓库
